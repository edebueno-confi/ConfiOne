# Proposed Phased Backlog

Este backlog é proposta para avaliação da direção.

## Fase 0 — Fechamento do Context Pack

- Revisar este pacote.
- Validar divergências e decisões pendentes.
- Definir escopo do próximo macro-lote.

## Fase 1 — Release Dashboard + Central

- QA final autenticado.
- Polimento visual apenas das superfícies de release.
- Garantir filtros, loading, erros e responsividade.
- Validar integrações HubSpot/OMIE em ambiente alvo autorizado.
- Definir usuário viewer/QA e rotas permitidas.
- Preparar runbook de deploy sem executar deploy até aprovação.

## Fase 2 — Central de Ajuda rica

- Reprocessar assets dos artigos.
- Melhorar diagramação de artigo.
- Normalizar contato via configuração global/rodapé.
- Garantir busca, categorias, relacionados e estados vazios.

## Fase 3 — Modelo B2B/CS

- Fechar taxonomia de cliente/tenant/grupo/entidade legal.
- Consolidar cockpit Clientes B2B.
- Consolidar carteira CS editável.
- Popular seed real auditável a partir de HubSpot/planilha quando autorizado.

## Fase 4 — Acessos e áreas internas

- Matriz área/função/perfil/telas.
- Dependências automáticas entre telas.
- Convites e gestão de usuários.
- QA com perfis reais.

## Fase 5 — Operação suporte/produto

- Fila e tickets com UX final.
- Handoff para produto/engenharia.
- Evidências/anexos.
- SLA e automações conforme regra aprovada.

## Fase 6 — Hardening para produção

- Testes completos.
- RLS e isolamento.
- Observabilidade.
- Rate limits de integrações.
- Runbooks de incidentes.
- Deploy controlado.

## Macro-lote futuro — Governança documental e reconstrução do Diário

- Classificar documentos atuais.
- Definir fonte canônica.
- Arquivar documentos obsoletos.
- Atualizar narrativa da jornada.
- Criar índice cronológico.
- Relacionar decisões, arquitetura, execução e impactos.
- Permitir leitura dos Markdown originais.
- Criar status visual de documento atual, histórico ou substituído.
- Validar permissões de documentos internos.
- Garantir que arquivos sensíveis nunca sejam publicados.
- Preservar `/admin/build-journal` como camada narrativa e Product Docs como leitor governado.
- Não usar o Diário como fonte oficial de decisão técnica.
